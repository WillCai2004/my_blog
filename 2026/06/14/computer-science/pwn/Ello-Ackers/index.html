write shellcode that reads /flag , but with a byte blacklist: the byte 0x48 (ascii char: ‘H’) cannot be used in the shellcode. The x86-64 REX.W prefix ( 0x48 ) is present at nearly all 64bit operations ( mov rdi, rsp , mov rbx, imm64 , etc.) → a naive amd64 shellcode will fail.

# 1. How this challenge works

The hint: this challenge requires that your shell code has no H bytes! — meaning we can’t use the byte 0x48 in our shellcode ( 0x48 is ASCII 'H' , not lowercase 'h' which is 0x68 ).

0x48 is the REX.W, and it shows up in most of your 64-bit instructions: mov rdi, rsp ( 48 89 e7 ), mov rsi, rsp ( 48 89 e6 ), mov rbx, imm64 ( 48 bb … ), etc. Therefore, we have to write shell code that completes open/read/write without ever emitting REX.W.

# 2. Ideas for avoiding REX.W

Two key tricks for not using 0x48 :

  • using push/pop instead of mov reg, rsp: push rsp; pop rdi ( 54 5f ), push rsp; pop rsi ( 54 5e ) — no REX.W
  • zeroing / small immediates via 32-bit ops: xor eax, eax ( 31 c0 ), mov al, imm ( b0 .. ), xor esi, esi ( 31 f6 ) — none contain 0x48 .

The whole logic, kept REX.W-free:

open("/flag", 0)          ; build "/flag\0" on the stack, then push rsp; pop rdi
read(fd, rsp, 0x7f)
write(1, rsp, bytes_read)

# 3. Pitfalls / key points

  • REX.W ( 0x48 ) is everywhere: any mov/add/... on a 64-bit rXX register carries it by default. Swap to the 32-bit equivalents (the high 32 bits are zero-extended for free) and use push/pop to move the stack pointer around — that avoids 0x48 entirely.
  • Writing /flag onto the stack without 0x48 : mov dword [rsp], "/fla" ( c7 04 24 .. ) + mov byte [rsp+4], 'g' ( c6 44 24 04 .. ) — neither encoding contains 0x48 .

# 4. Takeaways

  • General way to beat a byte blacklist: replace "the encoding of the instruction that contains the forbidden byte" with an equivalent sequence that encodes differently.
  • Toolbox for avoiding REX.W: push rsp / pop rdi (move the stack pointer), 32-bit arithmetic (auto zero-extends), xor r32, r32 to zero, mov al, imm to set the syscall number — together they let you write an almost purely 1-byte-prefix amd64 shellcode.
