The first-stage is only 0x06 = 6 Bytes (this shellcode area is RWX; 0x1000 in size). Given that there is no way to fit both a read + ret into the 6-byte buffer space, the exploit relies on exploiting the original state of the registers (at which point rax = 0 and rdx = shellcode page address ) to create a 6-byte read stager to pull the second stage back over this same page, followed by natural fall through to run the second stage at page+6 .

# 1. Mechanics of the problem

  • A 6-byte input landing on the RWX shellcode page.
  • Registers relevant to how the shellcode will start: rax = 0 (perfect for SYS_read), rdx = shellcode page address (also perfect for the buffer).

# 2. Strategy

Six-bytes is barely enough space to build a minimal "read" stager — because we don't need to initialize either of the two registers that we know are already initialized on the entry to the shellcode ( rax = 0 already and rdx = this page already).

xor edi,edi ; 31 ff rdi = 0 (stdin) 2B
push rdx ; 52 rsi = rdx = this page 1B
pop rsi ; 5e 1B
syscall ; 0f 05 read(0, page, ... ) 2B Total 6B

i.e., a read(0, shellcode_page, ...) , reading stage2 back over the first part of this page.

Passing control through natural fall through: Once syscall returns, execution will resume right at shellcode_page + 6 (next to the end of the first stage). We can therefore append six NOPs to stage2, so that when we actually pull the payload back over here it lands at +6 and gets executed:

stage2 = b'\\x90' * 6 + real_shellcode

Total: 6B stage1 -> read stage2 onto this page -> after syscall finishes executing, continue executing at page+6 -> execute cat("/flag"). .

# 3. Possible pitfalls & important considerations

  • Use all that you see useful about the entry registers: rax=0 (the syscall number for read ) and rdx=page_address (ready-for-use buffer) provide us with enough info to cut corners and save bytes — therefore it isn’t necessary to add any instructions to prepare these registers before they’re used in our stager (hence why we were able to keep everything inside a 6-byte limit).
  • There’s simply too little room for a ret: if we’d appended a c3 (a ret instruction), the stager would’ve taken seven bytes. So instead, use natural fall-through: once read has written to this page, execution will naturally flow from here directly to page+6 ; line-up the beginning of stage2 with six NOPs.
  • Check your assumptions about the initial registers through experimentation: Each challenge might have different starting register values; experimentally determine what rax/rdx are, etc. Don’t guess wrong based only on a particular low-order byte of one of those.

# 4. What we learned

  • Shortest stagers rely on “borrowed pre-initialized registers”: If we only have enough bytes for a single syscall, don’t spend even a single precious byte initializing any register you know will be available to us on entry into the shellcode ( rax = syscall number, rdx = usable buffer); Use every last byte of your budget creating the syscall.
  • Instead of jump/return, fall through: Don’t bother including the bytes for jmp/ret , but instead let read overwrite this page; Let execution automatically pick up after the stager; Make sure to include an equivalent number of NOPs at the beginning of stage2.
  • Compare to Pocket Payload: Twelve-bytes is sufficient to bootstrap ROP/SROP; But we only have enough space for a six-byte minimal read stager — i.e., there’s no space for a ret.
